注入系统提示词与内置记忆库的语言直接影响每轮 token 成本。2026-09-09 用 `o200k_base` 在本机实测。

## 实测数据

- 同一句 Fork-First 规则：中文 140 字符 = **104 token**；英文同义 361 字符 = **80 token**（英文省 23%）。
- 中文只占 37–41% 的字符数，却多花 34–55% 的 token——汉字几乎不产生词合并，平均 0.83 token/字；英文平均约 5.4 字符/token。
- 第三方 6 组配对基准（o200k_base）：中文 1.06–1.55x，平均 **1.34x**；日文 1.73x。旧 `cl100k_base` 下中文达 2.08x，分词器代际差异很大。
- **厂商不可外推**：以上是 OpenAI 分词器数据，不能套用到 G​emini/Claude/DeepSeek/Qwen；要准数必须调对应厂商的 `count_tokens`。

## 关键陷阱：限额按字符，成本按 token

Hermes 内置库限额是 `memory.memory_char_limit` / `user_char_limit`（默认 3000/2000 **字符**）。同样 3000 字符预算：全中文 ≈ 2490 token，全英文 ≈ 615 token。**英文版表达同样信息需要约 2.5 倍字符**，所以直接翻译会撑爆限额——必须先把内容压掉约 60%（低频条目迁 OpenViking）再译。

## 落地结果（2026-09-09）

SOUL.md / MEMORY.md / USER.md 三文件全量译英 + 压缩，每轮注入 **3430 → 2004 token（-42%）**：

| 文件 | token 变化 | 字符限额 |
|---|---|---|
| SOUL.md | 826 → 797 | 无 |
| MEMORY.md | 1525 → 740 | 2769/3000 |
| USER.md | 1079 → 464 | 1996/2000 |

**Why:** 这三份随系统提示词全量注入每一轮，是最高频复现的开销；中文在其中占比达 49%（MEMORY.md）。

**How to apply:** 想省钱先做减法再谈换语言；改完必须实测字符数确认未超限。另外 SOUL.md 位于 cache 前缀最头部，改动会失效其后整段前缀一次，属一次性成本，不值得为几十 token 反复改。输出语言是另一本账——用户若不擅长英文，输出侧保持中文的体验收益大于 token 成本。
