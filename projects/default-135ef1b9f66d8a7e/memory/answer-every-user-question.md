用户的一条消息里常带多个问题（例如「还有 edge://inspect 的其它页面会不会有用」），并清楚记得哪些没被回答。2026-08-22 我曾把答案塞进括号里一句带过，用户连续追问三次后才得到正式回答。

**Why:** 用户以问题清单的方式沟通，未回答的问题对他完全可见，被忽略会造成挫败感、打断任务节奏。

**How to apply:** 回复前对照用户上一条消息逐条自查：每个问题是否都得到了成段、明确的回答；不要把答案藏在括号、附注或长文末尾一笔带过。

2026-08-25 同类教训的变体：汇报任务完成时我称"只剩四项遗留"，用户反问"只剩这四个了吗"——实际代码层/文档层还有十余项未完成（版本常量、错误策略、测试模式备份、旧核查基线等）。**汇报遗留项/完成度时必须对照最初完整发现清单逐项对账**（必要时用 grep 实证再回答），而不是只汇报当前阶段范围内的缺口；宁可列全，不可少报。
