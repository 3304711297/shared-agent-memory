2026-09-16，workbuddy2api 修「Hermes 已配置反代、软件却显示未配置」时，先写出的检测判据是「回环主机 + 路径含 `/v1`」。

**它当场抓到了错的服务**：探针第一次跑就报「已配置」，命中地址却是 `18080` —— 本机另一套 CPA 网关，不是本工具的 `8787`。若直接交付，用户会看到「已配置」而实际指向别人的服务，比原来的假阴性更难发现。加上端口比对（端口取自配置，不写死）后结果才正确。

**规则**：
- 「回环 + `/v1` 路径」在开发机上**不构成唯一性**，至少同时比 **scheme + 端口**；端口必须来自配置而非硬编码（本工具端口可被用户改）。
- 判定「已配置却显示未配置」时，**先确认检查的路径是不是当前路径，再决定改不改判据**。本例用户的配置路径一直是对的（`%LOCALAPPDATA%\hermes\config.yaml`），错的是**判据范围太窄**（只读顶层 `model` 段，而端点实际登记在 `providers.<name>` 下）——若一上来就去改路径探测，会修错地方。
- 扫描**所有**该地址可能出现的落点：顶层 `model`、`providers.<name>`、`model_aliases.<alias>`、`custom_providers[]`。用户完全可能一边用 A 订阅当默认、一边在 B 里挂本工具端点。
- 外壳改动要配**端到端探针**（临时读真实配置跑一次），单测全绿不代表判据在你的机器上成立——本例两条单测都没能暴露 18080 误认。

**注意**：修好检测 ≠ 用户能立刻看到。检测逻辑属软件侧，用户需重新构建才会生效；同时「删掉端点重新导入」这类客户端侧操作**改不了**软件侧判据，别把它当作解决办法推荐给用户（本例用户正是这么打算的，需明确劝阻）。
