# cangjie-distill — 长文本/长视频/书籍方法论蒸馏元技能

## 使命与定位
把书籍、长视频字幕、播客文字稿、课程访谈中沉淀的方法论，拆解成**原子化、可被 Agent 在真实决策场景中调用**的能力卡片（Capability Bundle），并编译为标准的单技能（single）或技能包（pack）。

**边界**：
- ✅ 做：方法论 / 决策框架 / 检查清单 / 思考原则 / 概念体系的工程化蒸馏
- ❌ 不做：纯信息压缩 / 浅层书摘 / 读后感抒情 / 作者人设扮演

---

## 核心方法论：RIA-TV++ 流水线（五阶段）

```
阶段 0: Adler 整书理解        → 产出 BOOK_OVERVIEW.md（骨架/术语/批判）
阶段 1: 5 个维度并行提取       → 候选单元池（框架/原则/案例/反例/词汇）
阶段 1.5: 三重验证筛选（知识验证） → 通过的单元（V1跨域 / V2预测力 / V3独特性）
阶段 1.6: 独立 Skill 晋级门    → 确定去向（promoted 独立发布 / router 汇聚）
阶段 2: RIA++ 构造能力卡       → 产出 R / I / A1 / A2 / E / B 六段能力卡
阶段 3: Zettelkasten 链接      → 建立跨卡引用（also_read）与共享 GLOSSARY
阶段 4: 压力测试与反例诱饵      → 设计触发正反用例（含兄弟诱饵负例）
阶段 5: 确定性编译与交付       → 编译为 single 路由技能或 compact pack 技能包
```

---

## 输入前置要求
在开始蒸馏前，**必须**从用户处明确以下要素（严禁无依据凭空脑补）：
1. **源文本材料**：PDF / EPUB / TXT / SRT 字幕 / 播客转写稿路径或全文。
2. **内容元信息**：
   - 书籍：书名 + 作者 + 出版年份
   - 视频/播客：标题 + 讲者/UP主 + 来源链接/分P
3. **交付形态倾向**：
   - `single`（默认推荐）：单技能路由入口 + 内嵌多张能力卡，保持技能库清爽，不增加全局意图负担；
   - `pack`：1 个总路由入口 + 少数（≤7个）高频核心晋级独立技能。

## 执行步骤规范（严格执行）

### 阶段 0：Adler 检视与理解
1. 通读或分块检视源文本；
2. 提炼 Adler 四步：
   - 结构（整篇架构与主线划分）
   - 解释（核心主张与关键命题）
   - 批判（前置假设、局限性与失效场景）
   - 应用（在工程/业务中的落地接口）
3. 产出 `BOOK_OVERVIEW.md`，向用户简要核对骨架。

### 阶段 1：五维提取
从材料中分类并行抽取候选单元：
- **框架（Framework）**：结构化决策模型或思维脚手架
- **原则（Principle）**：行动法则、启发式启示、检查清单
- **案例（Case）**：书中亲自践行的正向完整验证
- **反例（Counter-Example）**：踩坑记录、明确警告的失败模式
- **术语（Glossary）**：作者独创定义与专有名词

### 阶段 1.5：三重知识验证（Triple Verification）
对每个候选单元做严格质检，任一不满足即打入淘汰池：
- **V1 跨域复现**：文本中至少有 2 处独立场景佐证，非单次孤立灵感；
- **V2 预测力**：脱离原书具体案例后，能指导回答未明说的新场景问题；
- **V3 独特性**：包含非显而易见的洞察，非人尽皆知的通用常识。

### 阶段 1.6：晋级门审核（Promotion Gate）
- **独立意图**：用户是否有明确单独唤起它的高频诉求？
- **独立契约**：是否有独立的输入输出规范？
- **独立运行**：不依赖其他章节上下文是否可自洽运行？
- **晋级决策**：满足者设为 `promoted`（独立输出）；其余全部归入 `router`（作为卡片由主路由调度，保持 Lean）。

### 阶段 2：RIA++ 能力卡标准化
为每个通过验证的能力卡撰写标准六段（纯正文，不带额外 Frontmatter）：
- **R (Reading 原文精炼)**：原汁原味核心命题（引用不超过 150 字）
- **I (Interpretation 认知解构)**：本质原理与运行机制
- **A1 (Appropriation 场景对齐)**：在何时何地适用，前置条件是什么
- **A2 (Action 实施规程)**：清晰的 Step-by-Step 行动指南
- **E (Execution 执行案例)**：输入/处理/输出的完整模拟示范
- **B (Boundary 禁忌边界)**：在何种场景下失效、禁止使用的红线

### 阶段 3 & 4：Zettel 链接与评测
- 梳理各能力之间的依赖、递进与冲突关系，生成 `GLOSSARY.md`；
- 设计正向触发提示词（Trigger Prompts）与兄弟能力诱饵负例（Negative Prompts）。

### 阶段 5：产出与安装交付
将编译好的 Skill（`SKILL.md`）存入用户工作区或技能库，格式严格遵守本地规程：
- Frontmatter 的 `description` **前 35 字符必须为中文高频动词置顶**，规避前 57 字符截断陷阱；
- 遵循单一职责，保持依赖精简。

---

## 质量红线
1. **真实文本锚定**：无文字稿或未提供有效内容时，必须停下向用户索取，严禁脑补；
2. **严禁囫囵全收**：未经三重验证的素材坚决过滤，宁缺毋滥；
3. **杜绝技能通胀**：默认以 `single` 汇聚模式输出，除非用户明确要求独立拆解，避免技能池膨胀。
